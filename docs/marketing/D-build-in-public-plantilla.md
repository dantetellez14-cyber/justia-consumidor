## 📅 Cadencia recomendada

```
   X / TWITTER                     LINKEDIN
   ───────────                     ────────
   3 posts/semana                  1-2 posts/semana
   1 thread/semana                 1 thread cada 2 semanas
   Reply a 5-10 posts/día          Reply a 2-3 posts/día
                                   
   Duración total: ~30 min/día     Duración total: ~15 min/2x semana
```

**Total tiempo:** ~3-4 horas/semana. Ese es el costo de oportunidad. La pregunta es: ¿hay una mejor inversión de 4 horas para tu marketing pre-launch? Probablemente no.

## 📐 Las 7 plantillas que rotás

### 🟦 Plantilla 1 — "El compromiso público"

**Cuándo usarla:** Lunes / inicio de sprint
**Función:** Te obliga a entregar + genera expectativa

```
┌────────────────────────────────────────────────┐
│                                                │
│  Esta semana voy a:                            │
│                                                │
│  ✓ Terminar el módulo de mediación AI          │
│  ✓ Indexar 50 casos más de jurisprudencia      │
│  ✓ Cerrar la integración con Resend            │
│                                                │
│  Si no lo termino, posteo screenshot del       │
│  fracaso 😅                                     │
│                                                │
│  Día 47/180 hasta el launch de JustIA.         │
│                                                │
└────────────────────────────────────────────────┘
```

**Funciona porque:** vulnerabilidad + accountability público + conteo regresivo.

**Cuándo usarla:** Después de un sprint productivo
**Función:** Demuestra rigor técnico, atrae devs y técnicos

## 🎨 Anatomía de un post viral en X

```
┌─────────────────────────────────────────────────┐
│                                                 │
│  ⚡ HOOK (línea 1):                             │
│  Tiene que parar el scroll en <1 segundo.       │
│  Número, frase rara, contradicción, pregunta.   │
│                                                 │
│  ─── espacio en blanco ───                      │
│                                                 │
│  📖 CUERPO:                                     │
│  Ritmo corto. Frases de 1 línea. Pausa visual   │
│  cada 2-3 líneas (espacios en blanco son SEO    │
│  emocional).                                    │
│                                                 │
│  ─── espacio en blanco ───                      │
│                                                 │
│  🎯 PUNCH FINAL:                                │
│  Contradicción, conclusión memorable, o         │
│  pregunta abierta. NO termines con CTA seco.    │
│                                                 │
└─────────────────────────────────────────────────┘
```

**Hooks que funcionan:**

```
✓ "Cosa que descubrí construyendo X..."
✓ "[Número] [unidad]. Esa es la cantidad de..."
✓ "[Empresa famosa] te está cobrando algo que no sabés."
✓ "Día [N] construyendo [producto]:"
✓ "Esto va a sonar polémico pero..."
✓ "[Persona] me dijo: [frase]. Estaba equivocada."
```

**Hooks que NO funcionan:**

```
✗ "Hola comunidad! Quería contarles..."
✗ "Estoy emocionado de anunciar..."
✗ "Que tengan un excelente martes 🌟"
✗ "Reflexión del día:"
```

## 💡 Tips de aceleración

### 1. Repostear posts viejos exitosos
Cada 4-6 semanas, podés repostear tus mejores posts con un nuevo wrapper:
> "Hace 5 semanas posteé esto. Sigue siendo verdad. [post original]"

### 2. Conversaciones > monólogos
La cantidad de seguidores la genera el algoritmo, pero la **calidad** la generan las conversaciones. Replicar a otros founders del rubro suele convertir más que postear.

### 3. Evitá el "Twitter de devs en español"
Suele ser cámara de eco. Tu audiencia ideal está en:
- Founders LATAM (Andrés Bilbao, Marcos Galperin reply chain)
- Periodistas de tecnología
- Influencers de "consumidor enojado"
- Devs/IA en inglés (audiencia secundaria valiosa)

### 4. Tools para schedule
```
Gratis:    Buffer (3 posts en cola)
Económico: Typefully ($12/mes, threads scheduling)
Pro:       Hypefury ($29/mes, automations)
```

**Pero al inicio:** posteá manual. La iteración rápida importa más que la eficiencia.

## 🚫 Errores típicos de build-in-public

| Error | Consecuencia |
|-------|--------------|
| Solo postear cuando "tenés algo bueno" | Pierdes momentum. Postear consistente > postear perfecto. |
| Compartir métricas falsas o infladas | Si te pillan, game over. |
| Quejarte mucho ("este sprint salió mal otra vez") | La audiencia se cansa rápido. Vulnerabilidad ≠ drama. |
| Solo hablar de TU producto | Aburre. 70% sobre el problema, 30% sobre el producto. |
| No interactuar con replies | El algoritmo te penaliza. Respondé al menos las primeras 2 hs. |
| Volumen sin estrategia | 5 posts/día sin sustancia = unfollow. Calidad > cantidad. |
